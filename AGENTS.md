# Maintaining this Lean library

- Start with README.md, docs/RESULTS.md, and docs/MODULE_INDEX.md. The result catalog records mathematical statements, hypotheses, and public declarations.
- Preserve theorem hypotheses, parameter domains, exponent ranges, and quantifier order. Keep the public documentation centered on the results the library proves.
- Use the committed Lean toolchain and dependency lock. Keep autoImplicit=false and do not modify dependency sources to bypass proof errors.
- Do not introduce sorry, admit, project axioms, unsafe proof shortcuts, unlimited resource settings, or disabled linters. Full axiom verification permits only propext, Classical.choice, and Quot.sound.
- Use ContDiff ℝ ∞ for smoothness. In this Mathlib version, ω denotes analytic regularity.
- Keep mathematical declarations in the PlanarNikodym namespace. Organize modules by mathematical subject and make every library module reachable from import PlanarNikodym.
- Update docs/RESULTS.md when a public mathematical statement changes. After adding or moving modules, run python3 scripts/check_layout.py --write-index.
- The full verification entry point is bash scripts/check.sh. Run the health inventory after that check; package verified sources with python3 scripts/package.py and a new output filename.
- Verification summaries, source manifests, and logs are generated by the check scripts. Do not write fabricated successful build records or edit frozen verification evidence.
